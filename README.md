# منصة طلبات الشراء والفواتير — شركة إكس

نظام طلبات الشراء والاعتماد والتفويض والفواتير، مبني فوق محرك قواعد الشركة نفسه (`engine.js` و`enterprise.js`)
وبياناتها الحقيقية (`seed.json`، 280 طلبًا). التقنية: Node.js + Express + PostgreSQL، وواجهة عربية RTL للجوال أولًا،
ووكلاء AI عبر Claude API.

## التشغيل

```bash
cp .env.example .env   # ضع ANTHROPIC_API_KEY و JWT_SECRET طويلًا
docker compose up --build
```

- الواجهة: http://localhost:8080 — والـAPI عبر http://localhost:8080/api (أو مباشرة على المنفذ 3000).
- عند أول إقلاع تُطبَّق الـmigrations وتُعبَّأ القاعدة من `api/seed.json`.
- كلمة مرور كل الحسابات = `SEED_PASSWORD` (الافتراضي `Passw0rd!`).
- بعد تغيير الـschema: `docker compose down -v` ثم `up` (يحذف بيانات التطوير ويعيد التعبئة).

## البنية

```
api/src/xpo/engine.js       ← نسخة مطابقة حرفيًا لملف الشركة (اختبار يتحقق من التطابق)
api/src/xpo/enterprise.js   ← نسخة مطابقة حرفيًا لملف الشركة
api/src/services/xpo.js     محوّل: صفوف PostgreSQL ⇄ شكل الحالة الذي يتوقعه المحرك
api/src/services/*.js       خدمات: تحمّل الصفوف ← تستدعي XPO/XENT ← تحفظ النتيجة + سجل التدقيق، في معاملة واحدة
api/src/rbac.js             مصفوفة صلاحيات المسارات وأدوات الـAI
api/scripts/seed.js         تعبئة من seed.json بإعادة تشغيل كل طلب عبر XPO.assess بترتيب التاريخ
web/                        SPA بلا build، يخدمها nginx مع proxy لـ /api
```

## القواعد (من engine.js — المرجع)

- **حدود الاعتماد** (على الإجمالي شامل الضريبة 15%): أقل من 10,000 → مدير المشروع؛ 10,000 إلى 49,999 → + المدير المالي؛ 50,000 فأكثر → + الرئيس التنفيذي. المراحل بالترتيب.
- **مدير المشروع** يعتمد طلبات مشروعه فقط. لا يعتمد أحد طلبه، ولا يعتمد شخص مرحلتين.
- **التقديم** لمهندس الموقع، على مشروعه، مع مرجع عرض سعر إلزامي.
- **تجميع الاحتياج (split):** طلبات نفس الطالب والمشروع والمورد خلال 3 أيام تُجمع، ويُصعَّد المسار إلى حد المجموع. للمدير المالي (أو مفوَّضه الساري) فصل التجميع بسبب مكتوب.
- **التكرار (dup):** نفس الطالب ونفس الصنف (بعد التطبيع: بلوك=بلك، بورسلين=بورسلان…) خلال 7 أيام وبفرق مبلغ ≤ 0.5%. يُرفض الطلب حتى يؤكد الطالب أنه ليس تكرارًا (الرد 409 ثم `confirm_dup: true`).
- **التفويض:** يصدره المدير المالي فقط، لموظف مالية أو عمليات، لمدة أقصاها 31 يومًا، بلا تقاطع، ويقتصر على مرحلة المالي. يلغيه المالي أو الرئيس التنفيذي.
- **الإرسال للمورد** من المشتريات، وبعد اكتمال الاعتماد فقط. المورد يرى أوامره المرسلة بحقول محدودة.
- **الفواتير** (enterprise.js): مطابقة مع أمر الشراء بتفاوت 2% أو 500 ر.س أيهما أكبر، والكمية 1%، والضريبة 15%، والرقم الضريبي (15 رقمًا يبدأ بـ3)، وتكرار رقم الفاتورة. الحكم: مطابقة / للمراجعة / موقوفة. الترحيل للمالية، والموقوفة تحتاج تجاوزًا بسبب مكتوب.

## مطابقة seed.json

`npm test` يعيد تشغيل الـ280 طلبًا عبر المحرك ويقارن:

- **dup:** 7 طلبات، **مطابقة تمامًا** لـ`seed.dups`.
- **split:** 21 طلبًا، تشمل **كل** الطلبات التسعة في `seed.splits`، وكل مجموعة تُصعَّد للمستوى المتوقع (`need_level`).
  الـ12 الإضافية سببها أن `engine.js` يجمع خلال **3 أيام** (`GROUP_DAYS`)، بينما بُنيت `seed.splits` على طلبات **اليوم نفسه**.
  القرار المعتمد: قاعدة `engine.js`. الإضافية: 0103+0116، 0117+0124، 0180+0192، 0182+0191، 0263+0270، 0264+0280.
- علامات التدقيق الأصلية في الإكسل (`after_reject`، `missing_cfo`، `missing_ceo`، `near_threshold`، `no_approver`) محفوظة مع الطلب،
  والصف الأصلي كاملًا في `requests.legacy`.

## انحرافات مقصودة عن ملفات الشركة (بالكود المحيط، لا بتعديل الملفات)

1. **سجل التدقيق:** نفس بنية السلسلة (بصمة السابق + القيد)، لكن بـSHA-256 بدل دالة البصمة غير التشفيرية (53 بت) في `engine.js`، لأن تزوير قيد مع بصمة صحيحة بها ممكن عمليًا. الجدول append-only بـtrigger، و`GET /api/audit/verify` يتحقق من السلسلة كاملة.
2. **فصل التجميع بعد اكتمال المراحل المتبقية:** يتحول الطلب إلى «معتمد» بدل أن يبقى معلّقًا بلا مرحلة.
3. **فاتورة معادة (rejected)** لا يمكن ترحيلها؛ تُدخل من جديد بعد التصحيح.
4. **تصدير CSV:** نصوص تبدأ بـ`= + - @` تُسبق بـ`'` قبل دالة التصدير، حماية من حقن الصيغ في Excel.

## مزوّد الذكاء الاصطناعي

يُختار تلقائيًا من متغيرات البيئة (لا قيم مكتوبة في الكود):

| المتغير | الأثر |
|---|---|
| `OPENROUTER_API_KEY` + `OPENROUTER_MODEL` | إن وُجد المفتاح يُستخدم OpenRouter (`/api/v1/chat/completions`، صيغة OpenAI و function calling). الموديل إلزامي، ويجب أن يدعم استدعاء الأدوات. لفواتير PDF والصور يلزم موديل يدعم الملفات والصور. |
| `ANTHROPIC_API_KEY` (+ `CLAUDE_MODEL`) | يُستخدم عند غياب مفتاح OpenRouter. |
| لا شيء | مسارات `/api/ai/*` ترجع 503 ويعمل باقي النظام. |

التحويل بين الصيغتين كله في `api/src/ai/client.js`. حلقتا الوكيلين والأدوات والصلاحيات لا تعرف أي مزوّد يعمل.
ويُسجَّل المزوّد والموديل في `extracted_by` لكل فاتورة مستخرجة آليًا.

## ملاحظات للإنتاج

- غيّر `JWT_SECRET` و`DB_PASSWORD`، واضبط `SEED_ON_START=false` بعد أول تشغيل.
- ضع TLS أمام `web`، ولا تنشر المنفذين 3000 و5432 للعموم.
- اختبارات التكامل: `TEST_DATABASE_URL=postgres://... npm test` **تحذف** الـschema `public` في تلك القاعدة.
